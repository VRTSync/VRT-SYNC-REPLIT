# Task #398: Fix web portal map — layer switching, populated-sublayer defaults, irrigation rendering, satellite toggle

## What & Why

Audit: `docs/portal-map-audit-2026-08-03.md`. Four confirmed defects in `artifacts/web-portal/public/portal/pages/map.js`:

1. Map always opens on the **community** category (`activeCategory = 'community'`, lines 48 and 421) regardless of what data the community actually has.
2. Viewport is always framed by `fitToOutline` (in `loadCommunityOutline`, ~line 489) and rarely re-fit on category change, because most `syncVisibleLayers()` calls pass `fitMap = false`.
3. **Irrigation renders nothing but the outline.** When `controllerData` is non-empty, zone/controller geometry is withheld in *both* `pushLayersToIframe()` (~522) and `syncVisibleLayers()` (~573) on the assumption that markers will be drawn instead. If the marker push yields nothing, the user sees an empty map.
4. Selecting **Snow** or **Trees** shows an empty map: `sublayerState` initializes `true` only for `community` and `irrigation` (lines 67–72), and sub-layer rows render for every key in `LAYER_HIERARCHY` whether or not a layer with geometry exists.

Plus: no satellite toggle on web, though `mapBridge.setSatellite(on)` exists in the shared template.

**Desired default behavior (stated by Randy):** *when a layer category is selected, the map loads with all populated sub-layers displayed and framed.*

## Out of scope

- Changing basemap tile providers (separate task — touches the shared template and mobile).
- The portfolio portal map (task #397) — but **this task must land first** so #397 doesn't copy the broken defaults.
- Map Creator, mobile app, admin map pages.
- Any API or schema change.

## Done looks like

- Opening the map lands on a category that **has data**, with all of that category's populated sub-layers visible and the viewport fit to them.
- Switching categories immediately shows every populated sub-layer of the new category and re-fits the map.
- Irrigation displays geometry whenever geometry exists — marker substitution only replaces geometry when markers were actually sent.
- Sub-layer rows reflect reality: populated ones checked and interactive; unpopulated ones either hidden or shown disabled with a "no data" hint (pick one, state which).
- A Map/Satellite toggle appears on the portal map and persists across navigation.
- Categories with no data show a clear empty state instead of a blank map.
- HOA, PM, and contractor map screens all behave correctly (all three use this file).

## Steps

### 1. Compute what's populated, once per load

- After `mapLayers` are fetched (and `_geojson` hydrated), build:
  ```js
  populated[cat][sub] = true   // a layer exists for that pair, isEnabled !== false, and has geometry with ≥1 feature
  ```
- Derive `populatedCategories` = categories with ≥1 populated sub-layer.

### 2. Data-driven initial category and sub-layer state

- Replace the hardcoded `activeCategory = 'community'` (lines 48 and 421) with: first category in `LAYER_HIERARCHY` order that is populated; fall back to `'community'` only if none are.
- Replace the `(cat === 'community' || cat === 'irrigation')` initialization (line 70) with `populated[cat][sub]` — every populated sub-layer starts visible, everything else starts off.

### 3. Sub-layer panel reflects reality

- In `renderSublayers()`, render populated sub-layers normally. For unpopulated ones, either omit them or render disabled with a muted "no data" label — choose one and note the choice.
- If the active category has zero populated sub-layers, render an empty state in the panel and over the map: e.g. "No irrigation data mapped for this community yet."

### 4. Fix the irrigation suppression rule

- Make `pushIrrigationToIframe()` report whether it actually sent markers (e.g. return the count sent by `sendIrrigationMarkers`).
- Track that result (`irrigationMarkersSent > 0`) and use **it** — not `controllerData.length > 0` — as the condition for excluding `controller`/`zone` geometry in `pushLayersToIframe()` and `syncVisibleLayers()`.
- If markers were not sent, push and show the raw geometry so something always renders.
- Add a code comment stating the rule: *geometry is only withheld when a confirmed non-empty marker set replaced it.*

### 5. Fit the map to what's visible

- Call `syncVisibleLayers(true)` on: initial render, category change, and sub-layer toggle that changes visible content.
- In `loadCommunityOutline()`, call `fitToOutline` **only** when the active category is `community` or when no other geometry is visible; otherwise let `fitToContent` frame the visible layers.
- Guard against stale re-entrancy using the existing `renderGeneration` counter so a slow fetch can't paint over a newer category selection.

### 6. Satellite toggle (web)

- Add a Map / Satellite toggle to the map toolbar, calling `cmdToIframe('setSatellite', bool)`.
- Persist the choice in `localStorage` (single shared key, e.g. `vrt_map_basemap`) so it survives navigation and page loads.
- Match the visual style of existing map controls; place it where the mockup's "Satellite" control sits.

### 7. Verify

For a community with irrigation, trees, and snow data:
- Initial load: opens on a populated category, all its populated sub-layers visible, map framed on them.
- Switch to Irrigation → zones/controllers/backflow etc. all render; switch to Trees → trees render; switch to Snow → snow sub-layers render. Each re-fits.
- Toggle individual sub-layers off/on → visibility updates without losing frame.
- Community with **no** irrigation data → Irrigation shows the empty state, not a blank map.
- Irrigation with controller assets synced → markers render; irrigation with no marker data → raw geometry renders (regression test for defect 3).
- Satellite toggle switches imagery and persists after navigating away and back.
- Repeat as `hoa_admin`, `property_manager`, and `contractor` — all three share this file.
