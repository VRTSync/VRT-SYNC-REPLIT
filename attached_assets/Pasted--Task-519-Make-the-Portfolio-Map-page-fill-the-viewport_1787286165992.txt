# Task #519: Make the Portfolio Map page fill the viewport height

*Ready to hand over. Number assigned locally — see the note in #516.*

## What & Why

The Portfolio Map is the client's opening screen and the map is the entire point of it. Today the map renders at a **fixed 560px** regardless of display size, so on any normal desktop it occupies roughly the top half of the window with dead space below it. The taller the monitor, the worse it looks — the map never grows.

Make the map and its control rail fill the available viewport height, so the page uses the whole workspace.

## Root cause — a fixed pixel height, plus three things that would block a fix

Verified at `9a4af6c`.

**`portfolio.css:1391`** is the direct cause:

```css
.pfm-map-wrap {
  position: relative;
  ...
  margin-bottom: 14px;
  height: 560px;        /* ← fixed, never grows */
}
```

Changing that number alone will **not** work. Three ancestors prevent a percentage or flex height from resolving:

| Where | Rule | Why it blocks |
|---|---|---|
| `portfolio.css:1122` | `.pfm-page { max-width: none }` | no height, no flex context |
| `portfolio.css:1127` | `.pfm-body { align-items: flex-start; min-height: 600px }` | `flex-start` stops children stretching; `min-height` is a floor, not a fill |
| `portfolio.css:70` | `#main { flex: 1; padding: 24px 32px }` | grows with content; never constrains it |

`#app` is `min-height: 100vh` (line 51), not `height`, so `height: 100%` chains will not resolve either.

## Acceptance criteria

### 1. Establish a height chain on the map page only

```css
.pfm-page {
  display: flex;
  flex-direction: column;
  height: calc(100dvh - 48px);   /* 48px = #main's 24px top + 24px bottom padding */
  min-height: 520px;             /* floor for short windows */
}

.pfm-body {
  flex: 1;
  min-height: 0;                 /* REQUIRED — see the note below */
  align-items: stretch;          /* was flex-start */
  /* drop min-height: 600px — the page floor replaces it */
}

.pfm-map-area {
  min-height: 0;                 /* REQUIRED */
}

.pfm-map-wrap {
  flex: 1;
  min-height: 0;                 /* REQUIRED */
  height: auto;                  /* was 560px */
  margin-bottom: 0;              /* was 14px — nothing follows it now */
}
```

**`min-height: 0` on every flex child in the chain is not optional.** Flex items default to `min-height: auto`, which refuses to shrink below content size. Omit it and the map will grow past the viewport and reintroduce page scroll instead of fitting — the most likely way this task ships looking broken.

Use `100dvh`, not `100vh`. If a `dvh` fallback is wanted, precede it with a `100vh` declaration.

**Scope this to `.pfm-page`.** Do **not** put `height: 100vh` on `#app` or `#main` — Dashboard, Locations, Work Orders and Groups all rely on normal document scroll and would break.

### 2. The rail scrolls internally

`.pfm-rail` is `align-self: stretch` already, so it will now be full height. Its content (group checkboxes, toggles, selected-location card, layer breakdown) can exceed that on a short window or a long group list.

Give the rail's scrollable region `flex: 1; min-height: 0; overflow-y: auto`, keeping `.pfm-rail-head` fixed at the top so the heading doesn't scroll away. The rail already has `display: flex; flex-direction: column; overflow: hidden`, so this is a small addition.

### 3. ⚠️ The map is an iframe and must be told it resized

**This is the part that will break if it is skipped.** The map renders in `.pfm-iframe` inside `#pfm-map-wrap`. Leaflet caches its container size; when the container resizes without a corresponding `invalidateSize()`, tiles render at the old dimensions — grey bands down the side or bottom, and pin positions drift from where they should be.

Today the height is fixed, so this never happens except on expand — and `map-render.js:906` already handles that case with `setTimeout(… invalidateSize(), 270)`. **Making the height fluid introduces resizes that nothing currently invalidates**: window resize, rail content changing, browser zoom.

Attach a `ResizeObserver` to `#pfm-map-wrap` that calls `_renderer.invalidateSize()`, debounced ~120ms. Tear it down in the page's existing `_teardown()` — the map page is a SPA route and an observer surviving navigation is a leak.

Use the renderer's existing `invalidateSize()` (exposed at `map-render.js:794`). **Do not add a second resize path or a parallel implementation** — the shared renderer is the one implementation and stays that way.

Note the `ResizeObserver` already in `map-render.js:1139` is for compact mode below 900px and is unrelated. Do not overload it.

### 4. Preserve the narrow-viewport stacking

The `@media (max-width: 860px)` block at `portfolio.css:1408` stacks the rail above the map. Full-height must **not** apply there — a stacked rail plus a flexed map inside a `100dvh` page crushes both.

Inside that media query, reset `.pfm-page` to `height: auto` and restore a fixed `min-height` on `.pfm-map-wrap` (the existing `380px` is fine).

### 5. Leave the expand button alone

`#pfm-map-wrap.pfm-map-wrap--expanded` at `portfolio.css:2127` is `position: fixed; inset: 0; height: 100vh` with id+class specificity, so it still overrides the new `flex: 1`. **I verified this selector exists and is wired** — `map.js:427` passes the class into `renderExpandButton`. It is not dead code.

It becomes less necessary once the map is full-height, but it also hides the rail, so it keeps its own value. Confirm it still enters and exits cleanly; do not remove it.

## How to verify

Desktop first, since that is where the complaint originates.

- [ ] At 1920×1080 the map fills from below the rail heading to the bottom of the window, with no dead space and **no page scrollbar**.
- [ ] At 2560×1440 it is taller still. The map grows with the window — this is the actual acceptance test, not any specific pixel height.
- [ ] The rail is the same height as the map, top and bottom aligned.
- [ ] Resize the window slowly from tall to short and back. **No grey bands, no clipped tiles, pins stay on their locations.** This is the `invalidateSize` test.
- [ ] Browser zoom to 150% and back — same result.
- [ ] Shrink the window until the rail's content overflows. The rail scrolls internally; the heading stays put; the page itself still does not scroll.
- [ ] Below 860px the rail stacks above the map and the map shows at its `380px` min-height, as before.
- [ ] Expand button enters full-screen and exits back to the flexed layout cleanly, both directions, twice.
- [ ] Navigate away to Dashboard and back to Map three times. Map still sizes correctly, and **no duplicate `ResizeObserver`** — confirm teardown by checking the observer count or logging in `_teardown()`.
- [ ] Dashboard, Locations, Work Orders and Groups all scroll normally and are visually unchanged.
- [ ] Pin click still fills the rail card; "Open property map →" still navigates.
