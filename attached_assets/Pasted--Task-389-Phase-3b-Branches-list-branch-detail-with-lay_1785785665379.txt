# Task #389: Phase 3b — Branches list + branch detail with layer tabs

## What & Why

The Branch Portfolio has a working shell and Dashboard (#388). This slice adds the two pages that make it useful: the **Branches list** and the **branch detail view organized by map layer**.

Data comes from endpoints already built in #372: `GET /api/portfolio/branches` and `GET /api/portfolio/branches/:communityId`. No API changes.

## 🎨 Design reference

**`mockups/pnc-branch-portfolio-v4.html` is already in the repo** (copied in #388). Open it and match:

- **Branches page**: the "Portfolio Coverage" navy anchor band (asset-type breakdown bar + legend), filter chip row, then the branches table.
- **Branch detail**: the **Branch Selector block** above the branch name (small uppercase "BRANCH SELECTOR" label, dropdown pill showing branch name + code, ‹ › prev/next arrows), then the branch title row, then the **layer tab bar**, then per-layer content.
- **Layer tab pattern**: `Summary · Site Grounds · Irrigation · Trees · Snow`, each with an asset count chip and its own underline color (teal / lime / blue / green / slate).
- **Per-layer page structure** (identical for every layer): KPI strip → **full-width map panel** → two-column row (inventory | service history) → optional third row (open items | documents).

## Core principles (do not deviate)

- **Layer tabs are data-driven from `map_layers`** returned by `GET /api/portfolio/branches/:communityId` → `layers[]`. Do NOT hardcode a list of five layers. A community with different layers (pet stations, parking sweeping) must get those tabs automatically. The mockup's five are just PNC's expected set.
- **Summary is always present** as the first tab; the rest come from the API in the order the layers are returned.
- **Snow content is the same layer template**, not a special case — its "service history" is the event log. If a `snow`-type layer exists, its page renders like any other layer plus the season summary block from `snowSeason` (which currently returns `null` — handle that).
- Escaping via `VRTUtils.esc` everywhere. No new API endpoints.

## Done looks like

- `#/branches` renders the anchor band, filter chips (All + one per group + "Has open items"), and a table: Code, Branch, Address, City, Group chip, Assets, Zones, Trees, Services YTD, Last Service, Open WOs. Row click → branch detail.
- `#/branch-detail/:id` (named-route pattern, `params.id`) renders the selector block, title row, and layer tabs.
- The branch selector dropdown lists all branches in the org (code + name + city) with an "← All Branches" item at top; ‹ › arrows step through branches in list order; selecting one re-renders in place (no full page reload) and updates the URL.
- Each layer tab renders: KPI strip for that layer, full-width map panel, inventory table, and service history — all from the branch-detail payload, filtered to that layer.
- **Empty and null states are honest**: a branch with no assets shows "No assets mapped for this layer yet" and an empty map panel with a "Not yet mapped" note; `snowSeason: null` shows "No winter data recorded"; zero services shows an empty-state row, not a spinner.
- Sidebar gains a **Branches** nav item; Dashboard's branch snapshot rows become clickable through to detail.
- No console errors; other portals untouched; typecheck/build pass.

## Out of scope

- Work Orders, Groups, Portfolio Map, Service History, Billing, Reports, Documents pages (later slices).
- Any map rendering library or real Leaflet integration — see step 4.
- API changes, mobile, admin hub.

## Steps

### 1. Branches page — `public/portfolio/pages/branches.js`

- Register `PortfolioRouter.register('branches', …)`; add the nav item in `portfolio.js`.
- Fetch `GET /api/portfolio/branches` (admin: append `organizationId`, using the existing helper in `portfolio.js`).
- Anchor band: totals across the returned branches (branch count, total assets, and the asset-type breakdown bar). If all counts are zero, render the band with a "No assets mapped yet" line instead of a zero-width bar.
- Filter chips: "All (n)", one per group from `PortfolioState.groups`, and "Has open items". Client-side filtering only.
- Table sorted by code. Row click → `PortfolioRouter.navigate('branch-detail', true, { id })`.

### 2. Branch detail shell — `public/portfolio/pages/branch-detail.js`

- Register `PortfolioRouter.register('branch-detail', …)` reading `params.id`; add the parse rule to `portfolio-router.js` mirroring how the admin router handles `organization-detail`.
- **Selector block above the title**: uppercase label "BRANCH SELECTOR", dropdown pill (branch name + code chip + caret), ‹ › arrows. Populate from `PortfolioState.branches`. Selecting/stepping updates `params.id`, re-fetches detail, and re-renders without a full reload.
- Title row: branch name (Outfit), `PNC Code <code>` in mono, address · city, and group chip if the branch is in a group.

### 3. Layer tabs — driven by the API

- Build the tab bar as: `Summary` + one tab per entry in `layers[]`, each showing `assetCount` as a chip.
- Assign tab accent colors by matching the layer's name/type against a small map (irrigation → blue, tree → green, turf/grounds/community → lime, snow → slate, default → teal). **Colors are cosmetic only — never use them to decide which tabs exist.**
- Tab switching is client-side against the already-fetched payload (no refetch per tab).

### 4. Layer content template (used by every layer tab)

- **KPI strip**: 3–4 tiles derived from that layer's inventory (e.g. asset count, distinct asset types, last serviced, open items touching that layer).
- **Map panel (full width)**: for this slice render a **placeholder map surface** styled like the mockup (light gradient background, panel header "…Map", "Open full map →" action) with a centered "Map integration coming in a later slice" note when there is no geometry, or the count of mapped assets when there is. Do NOT wire Leaflet or `/leaflet-map.html` yet — real map embedding is its own slice.
- **Inventory table**: rows from `inventory[]` filtered to this layer — asset type, count, and any per-type detail available.
- **Service history**: rows from `recentServices[]` filtered to this layer where the payload allows; if the payload cannot attribute a service to a layer, show the branch-wide list on the Summary tab only and an empty state on layer tabs, and note the limitation in a code comment rather than guessing.
- **Snow layer extra**: render the `snowSeason` block when present; when `null`, show "No winter season data recorded yet".

### 5. Summary tab

- Branch-level KPI strip (services YTD, open work orders, assets mapped, last service).
- Full-width map placeholder showing all layers.
- Two-column: recent services (branch-wide) | open work orders from `openWorkOrders[]`.

### 6. Verify

- As the PNC client user: Branches page lists all 10 with correct codes/addresses; filters work; row click opens detail.
- Branch detail: selector lists 10 branches, arrows wrap correctly at both ends, URL updates, no full reload.
- With zero mapped assets (current PNC state): tabs show only Summary (since `layers[]` is empty) — confirm this renders sensibly rather than an empty tab bar.
- After adding a map layer to one branch via the admin hub/Map Creator, that branch gains the corresponding tab automatically with no code change. **This is the acceptance test for data-driven tabs.**
- As admin with `?org=<id>`: same behavior.
- Side-by-side with the mockup at 1280/1440px.
