# Task #481: Remove the 60-second auto re-render from the portfolio portal

## What & Why

`portfolio.js` runs a timer that re-dispatches the current route every 60 seconds:

```js
_refreshTimer = setInterval(function () {
  var route  = PortfolioRouter.getCurrentRoute();
  var params = PortfolioRouter.getParams();
  PortfolioRouter.render(route, params);   // full teardown + rebuild of ANY page
}, AUTO_REFRESH_MS);
```

On the dashboard this merely flickers. On **branch detail** it destroys and rebuilds the page every minute: new map iframe, `ready` re-fires, the tab snaps back to Summary, sub-layer selections are lost, and the viewport refits — mid-interaction. It is the actual cause of the "resets every 60 seconds" behaviour (the earlier `ready`-guard work was necessary but could never fix this).

Applications do not re-render a page underneath the person using it. Replace the timer with patterns users expect: a visible staleness label, a manual refresh, and a quiet re-fetch when the user returns to the tab.

## Done looks like

- **No timer re-renders any route.** The user's page, scroll position, tab, map state, form input, and open menus are never disturbed by the passage of time.
- The header keeps its **"updated Xm ago"** label, accurate to within a minute.
- A **manual Refresh control** sits next to that label. Clicking it re-fetches the current route's data and resets the label. It shows a brief in-progress state and is disabled while in flight.
- **Return-to-tab refresh**: on `visibilitychange` → visible, if the data is older than **5 minutes**, re-fetch the current route once and update the label. If it is fresher than that, do nothing.
- The return-to-tab refresh must **not** run while the user is mid-interaction: skip it if the map panel is expanded, a modal or dropdown is open, or an input inside the page has focus. Re-check when that state clears.
- Behaviour is identical across all portfolio routes; nothing route-specific is hardcoded.
- No console errors; no duplicate timers left behind when navigating between routes.

## Steps

1. **Delete the auto-refresh timer** — remove `scheduleAutoRefresh()`'s `setInterval` that calls `PortfolioRouter.render(...)`, and remove `_refreshTimer` bookkeeping. Keep `AUTO_REFRESH_MS` only if still used by the staleness threshold; otherwise delete it.
2. **Keep the label ticking** — retain the lightweight `setInterval(updateRefreshLabel, 30000)`; it only writes text and touches nothing else. Confirm it does not re-render.
3. **Add the manual Refresh control** next to the label in the portfolio header: a small button (icon + "Refresh"). On click → `PortfolioRouter.render(currentRoute, currentParams)`, set `_lastRefreshTs = Date.now()`, update the label. Disable while the re-render runs.
4. **Add visibility-based refresh** — on `document.visibilitychange` to visible: if `Date.now() - _lastRefreshTs > 5 * 60 * 1000` **and** no interaction guard is active, re-render once and update the label. Guards to check: `.bmap-panel--expanded` present, any open modal/dropdown, or `document.activeElement` being an input/textarea/select inside the page container.
5. **Clean up on navigation** — ensure no stale intervals or listeners accumulate when moving between routes (register the visibility listener once at boot, not per render).
6. **Verify**
   - Open branch detail → Irrigation tab → uncheck a sub-layer → pan/zoom → **wait 3 minutes** → nothing changes: tab, toggles, and viewport all intact.
   - Click Refresh → data updates, label resets to "updated just now".
   - Switch to another browser tab for 6+ minutes, return → page refreshes once, label resets.
   - Switch away and back within 1 minute → no refresh.
   - Expand the map, switch tabs away for 6+ minutes, return → **no** refresh while expanded; collapse → refresh happens (or on next visibility change).
   - Work Orders page: open the Submit Request modal, leave the tab for 6+ minutes, return → modal and typed input are intact, no refresh.
   - Navigate between routes 10+ times → only one visibility listener and one label timer exist.

## Out of scope

- Live/data-only refresh that patches values without re-rendering (worthwhile follow-up for the dashboard; not this task).
- WebSocket or push-based updates.
- The admin hub's own refresh behaviour (internal tool, leave as is).
- Any change to route rendering itself.
