# Task #458: Hide "opened" dates on work orders (demo presentation)

## What & Why

Every work order in the PNC portfolio was created on the same day, so the portal reads "opened Aug 3" on all 15 items — which makes seeded data obvious. For tomorrow's demo, suppress the opened date rather than fabricating backdated timestamps.

**Small, cosmetic, reversible.** Nothing is deleted; only the display is hidden behind a single flag.

## Done looks like

- The portfolio Work Orders page no longer shows the opened date or the "N days open" text in the Open table.
- The branch-detail Open Work Orders list no longer shows "· opened <date>".
- Everything else on those rows is unchanged (title, branch, source, status, estimate).
- The Recently Closed table's Opened/Closed columns are also hidden (they would show the same tell).
- Implemented as one boolean constant, e.g. `var SHOW_WORK_ORDER_DATES = false;`, in each affected page file, with a comment explaining it exists for demo presentation and should be flipped back once real history accumulates. **No API or data change.**

## Steps

1. `artifacts/web-portal/public/portfolio/pages/work-orders.js`
   - Add the constant near the top.
   - Open table: drop the Opened column (header + cells) when the flag is false — do not leave an empty column.
   - Recently Closed table: drop Opened, Closed, and Days Open columns when false.
   - Keep the underlying data in the row objects so re-enabling is a one-line change.
2. `artifacts/web-portal/public/portfolio/pages/branch-detail.js`
   - Open Work Orders panel: render `pending` (status) without the `· opened <date>` suffix when the flag is false.
3. Verify: portfolio Work Orders page and branch-detail Summary show no dates; column headers and row cells stay aligned; no console errors; flipping the constant to `true` restores the previous display exactly.

## Out of scope

- Backdating or otherwise altering task data.
- The admin hub (internal — dates stay).
- Work-order detail/edit/cancel/comment functionality (separate task).
