# Task #385: Phase 3 — Branch Portfolio shell, login routing, and dashboard page

## What & Why

The commercial tier has schema (#361/#365), scoped API endpoints (#368/#372), and admin provisioning UI (#384). What's missing is the thing the client actually logs into: the Branch Portfolio portal.

This task builds the portal shell, wires `client_admin` login routing to it, and implements **only the Dashboard page**. Remaining pages (Branches, Branch detail, Work Orders, Groups, Portfolio Map, Service History, Billing, Reports, Documents) come as later slices.

## 🎨 Design reference — READ THIS FIRST

**`mockups/pnc-branch-portfolio-v4.html` is attached to this task.** Open it and match it: layout, spacing, color language, typography, component structure.

Key conventions from the mockup that must carry over:

- **Left sidebar navigation** (250px, navy gradient `#0C1D31 → #06101c`, teal `#25C1AC` active accent). NOT the topbar layout used by the existing HOA/PM/contractor portals.
- Content area **fills the remaining width** — no max-width cap.
- Fonts: Inter for UI, Outfit for display/headings (already loaded by other shells).
- **Panel headers**: white ground, Outfit 17px title, a small colored dot with a soft halo before the title, and a 2px "light sweep" underline that starts saturated at the left edge and dissolves to the neutral hairline across the panel. Domain colors: teal (default), blue (maps/irrigation), amber (needs action), green (completed), slate (winter), navy (summary).
- **Navy anchor band** at the top of each page containing that page's headline numbers and one small visualization (the `.anchor` / `.week-hero` pattern in the mockup).
- KPI tiles: tinted wash background, colored value, 3px colored bottom border.

Reproduce the mockup's *structure and styling*; the data comes from the API, so numbers will differ (a new org will show zeros — that is correct and must render cleanly).

## Done looks like

- `GET /web/portfolio/*` serves a new `portfolio-shell.html`, gated server-side to roles `client_admin` and `admin` (admin for support/preview).
- Logging in as a `client_admin` lands on `/web/portfolio/dashboard`; the login page's `roleMap` includes the new role.
- Sidebar shows the portfolio brand block, the org name, and nav items **for implemented routes only** (Dashboard now; others added as slices land) plus the user block at the bottom.
- Dashboard renders from `GET /api/portfolio/dashboard` + `GET /api/portfolio/me`: KPI tiles, the "This Week" navy anchor band with progress bar and day grid, group cards, and a branch snapshot table.
- A brand-new org with no data renders zeros and empty states — no `NaN`, no `—` where a 0 belongs, no console errors, no spinners that never resolve.
- Escaping via `VRTUtils.esc` on every interpolated value.
- 60-second auto-refresh with an "updated Xm ago" label, matching the admin dashboard's pattern.
- Existing HOA/PM/contractor/admin portals unchanged.

## Out of scope

- Any portfolio page other than Dashboard.
- Any API change — all data comes from #372's endpoints. If something needed is missing, stop and report rather than adding endpoints.
- Mobile app, admin hub, or the other portals.
- Branding beyond what the mockup shows (no logo uploads, no per-client theming).

## Steps

### 1. Shell — `artifacts/web-portal/templates/portfolio-shell.html`

- Model on `pm-shell.html` for structure and the `window.PORTAL_CONFIG` pattern, but with the **left sidebar layout from the mockup**:
  ```js
  window.PORTAL_CONFIG = { base: '/web/portfolio', allowedRoles: ['client_admin','admin'], label: 'Branch Portfolio' };
  ```
- Load `/common-static/utils.js` first, then the portfolio scripts.
- Sidebar markup: brand (`VRT` + teal `Sync`), sub-label "Branch Portfolio", nav list, a footer note area, and the user block at the bottom.

### 2. Server routes — `artifacts/web-portal/src/server.ts`

- `app.get("/web/portfolio", …)` → redirect to `/web/portfolio/dashboard`.
- `app.get(/^\/web\/portfolio\/.*$/, requireRole(["client_admin","admin"]), …)` → serve the stamped shell. Follow the existing pattern at lines ~333–366 exactly.
- Add `client_admin: '/web/portfolio/dashboard'` to the login page `roleMap` (line ~226).
- Add a `/portfolio-static` static mount for `public/portfolio/`, and include `/portfolio-static` in `.replit-artifact/artifact.toml` `paths` (this was the gotcha in #340 — missing it breaks routing in production). Extend the cache-stamp regex to cover `portfolio-static`.

### 3. Static app — new `artifacts/web-portal/public/portfolio/`

- `portfolio.css` — sidebar, layout, panels, anchors, KPI tiles, tables, per the mockup. Use CSS variables mirroring the mockup's `:root`. Do **not** import `admin.css` or `portal-ext.css`.
- `portfolio-router.js` — same named-route pattern as the admin router (`register(name, fn)`, `navigate(name, push, params)`, path parsing under `/web/portfolio/…`). Do not invent `:id` route patterns.
- `portfolio.js` — boot: `GET /api/auth/me` → verify role, `GET /api/portfolio/me` → org + branches + groups into a small state object, render sidebar (org name, nav), then dispatch the route. 401 → `/web/login`.
- `pages/dashboard.js` — the page itself.

### 4. Dashboard page content (from `GET /api/portfolio/dashboard`)

Match the mockup's dashboard, minus sections whose data doesn't exist yet:

- **KPI row**: Branches, Assets Mapped, Services Logged, Photo Documentation, Open Work Orders (click → route when that page exists; until then, no dead cursor-pointer).
- **"This Week" anchor band**: navy gradient, teal/amber progress bar (completed / needs attention / scheduled), stats (scheduled, completed, needs attention), and the 7-day grid with per-day service items and status colors.
- **Group cards**: one per group with color header and branch/service/on-time/open stats. If the org has no groups, show a single quiet empty state — do not render an empty grid.
- **Branch snapshot table**: code, name, group chip, services YTD, last service. Rows are not yet clickable (branch detail is a later slice) — no pointer cursor on them.
- Omit entirely for now: winter/snow band, billing callout, portfolio map — those belong to later slices with their own data.

### 5. Empty-state discipline

A freshly provisioned org has zero of everything. Every element must render honestly:
- counts show `0`, not `—` or blank
- "This Week" shows the day grid with "No services scheduled" rather than a collapsed band
- group cards / branch table show a one-line empty message
- the page never shows an infinite spinner or an error toast for "no data"

### 6. Verify

- Log in as the PNC `client_admin` → lands on `/web/portfolio/dashboard`, sidebar shows the org name, dashboard renders with zeros/empties and no console errors.
- Log in as `admin` → can reach `/web/portfolio/dashboard` (support preview).
- Log in as `hoa_admin` / `property_manager` / `contractor` → `/web/portfolio/dashboard` redirects to their own dashboard (server-side gate).
- Logged out → redirects to `/web/login`.
- Side-by-side against the mockup at 1280px and 1440px: sidebar, KPI row, anchor band, and panel headers match.
- Confirm `/portfolio-static` assets load in a production-style build (artifact.toml paths updated).
