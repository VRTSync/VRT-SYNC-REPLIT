# Task #399: Replace basemap provider — licensed tiles, config-driven, attribution, mobile parity

## What & Why

`lib/leaflet-template/src/` hardcodes two tile sources (~lines 149–156):

```js
streetLayer    = L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png', { maxNativeZoom: 19, maxZoom: 23 })
satelliteLayer = L.tileLayer('https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}', { maxNativeZoom: 19, maxZoom: 23 })
```

Problems:

1. **OSM's public tile server is not licensed for production/commercial app use** — its Tile Usage Policy prohibits systematic use by applications and is rate-limited. VRTSync is a paid product; this is a compliance and reliability exposure, not a style preference.
2. **Attribution is not displayed** (attribution control is disabled elsewhere in the codebase). Both OSM and Esri require visible attribution.
3. **Tiles blur past native zoom 19** while the map allows zoom 23 — precisely the zoom range where a bank lot or irrigation zone is inspected.
4. OSM street styling is visually noisy beneath colored asset geometry; a muted basemap reads far better.

This template is shared by **the web portals, the mobile app (`components/LeafletMap.tsx`), and Map Creator**, so one change fixes every surface — and one mistake breaks every surface. Hence its own task with mobile regression testing.

## Provider decision — DECIDED: Mapbox

Both basemaps come from Mapbox. A **public** token (`pk.…`) is supplied out-of-band and must be stored as a Replit secret named `MAPBOX_TOKEN` — **never committed to the repo, never hardcoded in the template or mobile source.**

Raster tile endpoints (512px tiles — set `tileSize: 512, zoomOffset: -1`):

```
street:    https://api.mapbox.com/styles/v1/mapbox/light-v11/tiles/512/{z}/{x}/{y}@2x?access_token=<TOKEN>
satellite: https://api.mapbox.com/styles/v1/mapbox/satellite-streets-v12/tiles/512/{z}/{x}/{y}@2x?access_token=<TOKEN>
```

- **`light-v11`** for the street/base layer: muted grey styling so teal/blue/amber asset geometry reads clearly on top. (If Randy prefers full-color streets, `streets-v12` is the swap — one config line.)
- **`satellite-streets-v12`** for imagery: aerial with road/label overlay, which orients a viewer far better than bare imagery on a parking lot.
- `maxNativeZoom: 22`, `maxZoom: 23` — Mapbox serves imagery deeper than the current Esri/OSM limit of 19, which fixes the blur at inspection zoom.
- Attribution string (required by Mapbox terms): `© Mapbox © OpenStreetMap` with the "Improve this map" link. The Mapbox wordmark requirement should also be checked against their current attribution guidance and satisfied.

## Done looks like

- Basemaps are defined in **one config object** in the leaflet template, not inline:
  ```js
  var BASEMAPS = {
    street:    { url: …, options: { maxNativeZoom, maxZoom, attribution } },
    satellite: { url: …, options: { … } }
  };
  ```
- The API key is **injected at build/serve time**, never committed. Web: served with the template from the web-portal (env var). Mobile: passed into the WebView HTML the same way other runtime values are.
- Attribution is visible on every map surface (web portals, mobile, Map Creator) and satisfies each provider's terms.
- `maxNativeZoom` matches the chosen provider's real limit; over-zoom beyond it is either allowed with an accepted blur or capped — state which and why.
- `mapBridge.setSatellite(on)` continues to work unchanged for all callers.
- Mobile: satellite preference persists across screens/sessions (currently local `useState` in `LeafletMap.tsx`, resets on mount) and the toggle is reachable in **all three** map screens — verify it isn't covered by `MapCreatorChrome` / `MapCreatorOverlay` in `mc-workspace/[id].tsx`.
- No regression in offline packs: confirm whether any cached tiles or map assets are bundled in offline packs and, if so, that the provider change doesn't invalidate them (report findings; do not redesign offline packs here).

## Out of scope

- The portal map layer-behavior fixes (task #398).
- Vector-tile styling / custom map design beyond selecting a provider style.
- Any change to `mapBridge`'s public method names or the `{ type:'cmd', fn, args }` protocol.
- Offline tile caching as a new feature.

## Steps

1. **Add the token as a Replit secret named `MAPBOX_TOKEN`** (value supplied separately by Randy — it is a public `pk.` token, but it must still live in secrets, not source). Do not commit it, do not inline it in the template, and do not log it.
2. **Refactor the template** (`lib/leaflet-template/src/`): replace the two inline `L.tileLayer(...)` calls with the `BASEMAPS` config; keep `streetLayer`/`satelliteLayer` variable names so `setSatellite` and any other references keep working. Add `attribution` to both layer options and ensure the attribution control is enabled on the map instance.
3. **Key injection — web:** the web-portal serves `/leaflet-map.html` from `LEAFLET_MAP_HTML`; substitute the key server-side (same place the HTML is stamped) so it is never in the repo. **Mobile:** pass the key into the WebView HTML alongside existing runtime values in `components/LeafletMap.tsx`.
4. **Mobile satellite persistence:** hoist `satelliteMode` out of component state into the app's existing persistence layer (MMKV for native / AsyncStorage fallback, matching how other prefs are stored) so the choice survives remount and screen changes.
5. **Map Creator visibility check:** confirm the satellite control is reachable in `mc-workspace/[id].tsx`; if `MapCreatorChrome`/`MapCreatorOverlay` covers it, adjust z-index/placement — do not remove or relocate Map Creator controls.
6. **Verify across every surface:**
   - Web: HOA, PM, contractor portal maps; admin map-layers page; `/pin-picker.html`.
   - Mobile: crew `(tabs)/map`, HOA `(hoa-tabs)/map`, Map Creator workspace — street and satellite, zoomed to 21–23 over a mapped property.
   - Attribution visible everywhere.
   - Toggle persists across navigation and app restart (mobile) and page reloads (web).
   - Confirm tiles load with the key and fail gracefully (no blank white map, log a clear error) if `MAPBOX_TOKEN` is missing.
   - Zoom to 22–23 over a mapped property and confirm imagery stays sharp (this is the regression the old `maxNativeZoom: 19` caused).
   - Grep the repo for any remaining `tile.openstreetmap.org` or `server.arcgisonline.com` references and confirm none are left (including `/pin-picker.html`).
