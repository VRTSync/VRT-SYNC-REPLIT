# Extend unmatched-code acknowledgement to the seasonal importer

*Follow-on to #544. Unblocks the seasonal contract import. Awaiting a number.*

## What & Why

The seasonal preview blocks Commit for the same reason the master bill did:

```
Blocking Errors — Commit is disabled
• Pilot community "FB45" — not found in the database
```

**#544's Out of scope was wrong, and that is my error.** It said:

> Seasonal import — its community resolution is org-wide and has no per-row PNC codes; leave it alone.

Both clauses are true and neither matters. The seasonal importer still validates the resolved communities against the **11-branch pilot list** (`KNOWN_PNC_CODES`, shared from `masterBillImporter`), finds 10, and blocks on the missing one — exactly as the master bill does. The guard is correct; it just has no acknowledgement path.

*Decision 2026-08-20: FB45 is not in the portfolio. Import without it.*

## This is simpler than #544 — the totals are already right

On the master bill, acknowledging FB45 had to **subtract** its row and amount from the preview totals (46 → 45 rows, $18,375.04 → $17,950.04).

Here, nothing changes. The seasonal importer expands across **communities it resolved**, not across the pilot list, so the projected counts on screen are already correct for 10 branches:

| | Shown | 10 × per-branch | 11 branches would be |
|---|---|---|---|
| Schedules | 30 | 3 × 10 ✅ | 33 |
| Total visits | 580 | 58 × 10 ✅ | 638 |
| Completed | 400 | 40 × 10 ✅ | 440 |
| Scheduled | 180 | 18 × 10 ✅ | 198 |
| Tasks | 150 | 15 × 10 ✅ | 165 |
| Completions | 80 | 8 × 10 ✅ | 88 |

**So acknowledgement here only lifts the block — it must not alter a single number.** If ticking FB45 changes any of those six figures, something is wrong.

## Acceptance criteria

### 1. Unmatched pilot communities become a structured list

As #544 did for the master bill: return them as a distinct field rather than pre-formatted strings in `blockingErrors`. Per entry: the code, and the community name from the pilot mapping table if known.

**No row count or dollar amount** — unlike the bill, a missing community here contributes no rows to skip. It simply is not expanded into.

### 2. One checkbox per unmatched community

```
☐  FB45 — 88th and Wadsworth — not in this organisation — proceed without it
```

Commit stays disabled until **every** unmatched code is ticked, and while any other blocking error exists. **No "skip all" button** — same reasoning as #544: each one should be a deliberate decision.

### 3. Totals do not move

The preview counts are computed from resolved communities and are already correct. Ticking a checkbox **must not recalculate them**.

**Add a line making the scope explicit**, so nobody reads 580 as a full-portfolio figure:

> *Projected for 10 of 11 pilot locations — FB45 excluded.*

### 4. Server-side re-validation

Same contract as #544: the commit request carries the acknowledged codes; the server verifies each appears in the preview's unmatched list and rejects otherwise. The checkbox is an affordance, not the authority.

### 5. Record it

Acknowledged exclusions appear in the commit summary and on the batch record, so a later reader can see the import covered 10 of 11 deliberately rather than wondering where the eleventh went.

### 6. Reuse #544's plumbing

The types, the server-side check, and the checkbox component should be shared, not reimplemented. If #544's implementation is master-bill-specific, generalise it rather than writing a parallel one — that is how the two importers diverged in the first place.

## What must NOT change

- **The blocking default.** Unacknowledged unmatched code → Commit disabled.
- **Any of the six projected counts**, before or after acknowledgement.
- **Every #541 assertion** — 18 rows, 2026 starts, ends after starts, Wednesday generation, the even-spread selection.
- **The master bill path**, already working.
- **`KNOWN_PNC_CODES`** — FB45 stays in it, for the reason given in #544: removing it moves the failure to the parse stage where no acknowledgement UI can surface it.

- [ ] Tick it. Commit enables. **All six counts are unchanged** — 30 / 580 / 400 / 180 / 150 / 80.
- [ ] The scope line reads *10 of 11 pilot locations*.
- [ ] Untick. Commit disables again.

- [ ] Every `service_date` is a Wednesday within `2026-04-01 … 2026-10-31`.
- [ ] Commit summary and batch record both note FB45 as an acknowledged exclusion.
- [ ] A commit naming a code the preview did not flag → rejected server-side.
- [ ] Re-commit the same file → nothing added.
