# Task #418: Branch detail — layer tabs render no geometry, and colors ignore admin settings

## What & Why

Two defects in the client portal's branch-detail maps, confirmed against the live deployment (FB02, PNC):

**A. Layer tabs render an empty basemap.**
On **Summary**, the map draws correctly (55 vector paths observed in the live iframe). Clicking the **Trees (35)** tab drops to **0 vector paths, 0 markers** — and no "not mapped" empty state either, so the user sees a blank map on a layer that has 35 assets and real geometry. The API is fine: `GET /api/portfolio/branches/:id/layers/:layerId/geojson` returns a populated FeatureCollection.

Likely cause — the map iframe is **moved between per-tab slots**. Summary renders into `#bmap-summary`; each layer tab renders into `#bmap-layer-<layerId>` (`branch-detail.js` ~218–256, ~491, ~558). When the iframe is relocated (or a new slot exists but the iframe isn't moved/re-mounted into it), Leaflet loses its container size and/or the layers aren't re-shown, leaving an empty map. Investigate the slot-move path first; do **not** assume it's the fetch (the fetch is proven working).

**B. Geometry colors ignore the admin's layer colors.**
`_pushNewLayers()` styles each layer with `_dotHex(accent)` (~62, ~105) — the portal's **tab accent palette** (teal/blue/green/lime/slate) — and stores that in `layerColors` for dim/restore. The layer's real color, set by an admin in the Map Layers page and stored on `map_layers.color`, is never used. So client-facing maps show VRTSync's tab palette instead of the colors the community was actually configured with.

Compounding: `getPortfolioBranchDetail()` only selects `id, name, type, asset_count` for layers — **`color` isn't in the payload at all**, so the front end couldn't honor it even if it wanted to.

## Done looks like

- Every layer tab with geometry renders that geometry. Trees (35) shows 35 features; Blue Grass shows its polygons; no blank maps where data exists.
- A layer with **no** geometry shows the existing "not yet mapped" placeholder — never a silent empty basemap.
- Switching between Summary and any layer tab, repeatedly and in any order, always renders correctly (no state that only works on first visit).
- Geometry is drawn in the **admin-configured color** for that layer (`map_layers.color`), on Summary and on layer tabs.
- Dimming inactive layers adjusts opacity/shade **derived from each layer's own color** — not a single hardcoded grey, and restoring un-dims back to the admin color.
- The community outline still renders as neutral context on every tab (existing behavior, keep).
- The tab accent palette remains for tab underlines/dots only — never for geometry.

## Steps

### 1. API — return the layer color

`artifacts/api-server/src/storage.ts`, `getPortfolioBranchDetail()`: add `color` (and `stroke_color`, `stroke_weight`, `fill_opacity` if cheap) to the layers query and to each returned layer object. These already exist on `map_layers`.

### 2. Front end — use the admin color for geometry

`artifacts/web-portal/public/portfolio/pages/branch-detail.js`:

- In `_pushNewLayers()` (~97–110), style each layer with `layer.color` from the API, falling back to `_dotHex(accent)` **only** when the API returns no color. Store the resolved color in `_bMap.layerColors`.
- In `_showLayerTab()` (~185–205), replace the hardcoded dim value `'#c8cdd4'` with a **derived** dim of that layer's own color (e.g. same hue at reduced opacity/lightness). Restoring uses `_bMap.layerColors[id]`.
- Leave `_dotHex()` in place for tab dots/underlines.

### 3. Front end — fix layer-tab rendering

- Determine why the map is empty on layer tabs. Start by verifying, in the browser, whether the iframe is present in the active tab's slot and whether `showLayerIds` is being sent with the active layer's id after the tab switch.
- Prefer **one persistent iframe moved into the active tab's slot** (or a single shared map panel rendered outside the tab panes) over per-tab iframes — whichever is simpler to make reliable. After any move/re-mount, call the bridge's `invalidateSize`-equivalent (the template already calls `map.invalidateSize()` on a timer at boot; ensure it's triggered after relocation) and re-issue `showLayerIds` + `fitToContent`.
- Guarantee the invariant: **after a tab switch, the active layer's id is in the set passed to `showLayerIds`, and its geometry is present in the iframe's layer cache.** Add a short code comment stating it.

### 4. Empty-state correctness

If a layer's GeoJSON is null/empty, show the existing placeholder in that tab's slot. A blank basemap with no message is never acceptable.

### 5. Verify (FB02, PNC — real data)

- Summary → all layers visible, outline drawn, colors match the admin's Map Layers settings.
- Trees tab → 35 tree features visible in the admin's tree color; inactive layers dimmed but present.
- Blue Grass, Landscape Beds → same.
- Hand Shovel / Ice Melt / Truck Plow (0 assets) → placeholder message, not a blank map.
- Switch tabs 6+ times in mixed order, including back to Summary → renders correctly every time.
- Change a layer's color in the admin Map Layers page, reload the client portal → new color appears.
- Confirm the client portal (`client_admin` login) shows the same as admin preview (`?org=`).
