# Task #489: Groups page in the Branch Portfolio portal

## What & Why

Groups exist in the database, are returned by `/api/portfolio/groups`, and render as small cards on the dashboard — but there is no page where a client can actually see how their portfolio is organized or compare one group against another. It is the one screen from the approved design set that has no route at all.

**Depends on #488** (group sets). Build against `/api/portfolio/group-sets`.

## Reference

The approved design is `marketing/portal-mockups/07-custom-groups.png` in the project folder. Match its structure; the CSS classes it uses (`.anchor`, `.group-grid`, `.gcard`, `.panel` + `.panel-head`, `.p-blue` / `.p-green` / `.p-amber`) all already exist in `portfolio.css`. **Do not add a new visual vocabulary** — if something in the mockup needs a class that isn't there, add it in the same idiom as its neighbours.

## Done looks like

- New nav item **Groups**, last in the sidebar, added to `NAV_ITEMS` in `portfolio.js` (~41).
- New route `groups` → `pages/groups.js`, registered the same way the other five pages are.
- Page structure, top to bottom:
  1. **Context header** — "Groups", subtitle "organize locations the way your business is structured".
  2. **Anchor band** (`.anchor`, the navy one) — "N group sets · M locations", a stacked coverage bar segmented by the groups of the **first** set, its legend, and right-hand stats for group-set count and total group count.
  3. **Group cards row** (`.group-grid` / `.gcard`) — one card per group in the first set, plus a dashed **"+ New group"** card at the end. The new-group card is **inert in this slice**: it renders, it is not clickable, and it carries no handler. Do not build creation UI here.
  4. **One panel per group set**, in `sortOrder`. Each panel's header is the set name, with the hint reading `group set · N groups`. Panel accent colour cycles `p-blue`, `p-green`, `p-amber`, `p-navy` by index so consecutive sets are distinguishable.
  5. Each panel's table: Group (as a coloured chip), Locations (the member codes, comma-joined), Assets, Zones, Trees, Services, Open, Photo Rate. Numeric columns right-aligned with the existing `.num` class.
- A set with no groups renders its panel with a single empty-state row, not a broken table.
- The synthetic **"Ungrouped"** set from #485 renders last and only when it has groups in it.
- Group chip colour comes from `group.color` when present, falling back to the same neutral the dashboard cards already use. **The colour comes from the group record — do not introduce a second place colours can be set.**
- Loading and error states match the other pages (`.pf-spinner`, and the `.pf-empty` failure message).
- Nothing on the do-not-claim list appears: no billing, no invoices, no exports, no on-time percentage.

## Steps

1. **Route + nav.** Add to `NAV_ITEMS` and the router's page map. Verify the `?org=` query string is preserved on navigation for the admin-preview path, as the other nav links do.
2. **Fetch.** One call to `/api/portfolio/group-sets`, org-scoped the same way the sibling pages scope theirs. No second request — the endpoint returns metrics already.
3. **Render** the five blocks above. Keep render functions small and named like the neighbouring pages (`renderAnchorBand`, `renderGroupCards`, `renderSetPanel`).
4. **Zones and trees per group** are not in the group-sets payload today. Rather than adding a second aggregation path in the page, either (a) extend `getPortfolioGroupSets` in #485 to include them, or (b) drop those two columns from the table. **Pick (a) if it is a small change to the existing metric SQL; pick (b) if it is not** — and say which in the implementation notes. Do not compute them client-side by summing branch records.
5. **Verify.**
   - Groups appears in the nav and routes cleanly; browser back/forward work.
   - Every set renders with correct counts; totals reconcile against the Locations page.
   - A location in three sets appears once in each of the three panels.
   - A set-less group appears under "Ungrouped" and nowhere else.
   - Empty set → empty-state row, no console errors.
   - Admin preview (`?org=<id>`) shows the right org's sets and the query string survives navigation.
   - A client user of another org cannot reach this data.
   - Page does not reset or re-render on its own while sitting idle for five minutes (this is the #481/#486 behaviour; if both have landed this should already hold).

## Out of scope

- Creating, renaming, deleting, or recolouring groups and sets.
- Assigning locations to groups.
- Drilling from a group into a filtered Locations view (good follow-up, not this slice).
- The comparison bar chart at the bottom of the mockup — **deliberately deferred**; it needs a considered metric choice and this slice should ship without it.
