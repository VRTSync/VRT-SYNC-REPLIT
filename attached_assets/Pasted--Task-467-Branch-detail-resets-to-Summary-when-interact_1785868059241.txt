# Task #467: Branch detail resets to Summary when interacting with the map

## What & Why

On the client portal's branch-detail page, interacting with the map — switching layers, toggling sub-layers, panning — snaps the page back to the **Summary** tab, shows all layers again, and refits the viewport, as though the page had just loaded. The user's tab, sub-layer selections, and zoom are all lost.

**Cause**: the `ready` handler in `portfolio/pages/branch-detail.js` (~348) unconditionally resets state:

```js
_renderer.on('ready', function (state) {
  _activeTabIdx = 0;                 // ← forces Summary
  _updateSublayerOverlay(0);
  _renderer.setActiveCategory(null); // ← shows all layers, refits
  …
});
```

`ready` is emitted by the shared renderer at the end of its push cycle (`map-render.js` ~560), so it fires on **every** re-initialisation, not just the first. Anything that re-inits the map (an iframe reload — which #457's `load` listener explicitly handles by resetting `ready` — or a redundant `load()` call) replays first-load behaviour.

**Second defect, same block**: `renderExpandedOverlays()` and three `addEventListener` registrations (`vrt-overlay-category-change`, `vrt-overlay-sublayer-change`, `layer-state-change`) live **inside** the `ready` handler with no removal. A second `ready` therefore attaches duplicate listeners, so each subsequent toggle fires its handler twice — compounding the thrash.

## Done looks like

- Switching category tabs, toggling sub-layers, panning, zooming, expanding, and collapsing never reset the page to Summary.
- Zoom/centre are preserved across sub-layer toggles (refit only on explicit user action — category change or an explicit "fit" control).
- If the map genuinely re-initialises (iframe reload), the user's current tab, checked sub-layers, and category are **restored**, not cleared.
- Overlay/event listeners are registered exactly once per page render; toggling a sub-layer fires its handler once (verify with a temporary counter or a log).
- First load still behaves as today: Summary tab, all layers visible, fit to content.
- Portal map and dashboard map preview unaffected.

## Steps

### 1. Make first-load behaviour single-shot per branch

- Add a guard, e.g. `_initialReadyDone` (reset to `false` only when `branchId` changes / on page render).
- In the `ready` handler:
  - **First ready for this branch** → current behaviour (Summary, all layers, fit).
  - **Subsequent ready** → **restore**: reapply `_activeTabIdx`, `_checkedSubLayers`, and the active category to the renderer; do **not** call `setActiveCategory(null)`; do **not** refit unless the viewport is otherwise undefined.

### 2. Register listeners and overlays once

- Move `renderExpandedOverlays(...)` and the three `addEventListener` calls **out** of the `ready` handler into the page-render path (after the panel exists), or guard them so they run once per render.
- If they must live in `ready` for data-timing reasons, keep references and remove previous listeners before re-adding.
- Verify no duplicate handlers: toggling one sub-layer produces exactly one state change.

### 3. Diagnose why `ready` fires repeatedly

- Add a temporary log at the emit site (`map-render.js` ~560) and at `load()` (~564) recording a reason/counter, and reproduce: open a branch, switch tabs, toggle sub-layers, pan, expand/collapse.
- **Report the finding in the implementation notes**: is `ready` firing because the iframe reloads (and if so, why — the iframe is supposed to be stable per #457), or because something calls `load()` more than once per branch?
- Fix the underlying cause if it is a redundant `load()`; if it is an iframe reload, identify what triggers it (CSS `display:none` on a parent, expand/collapse, or DOM manipulation of an ancestor can all reload an iframe in some browsers).
- Remove the temporary logging before finishing.

### 4. Preserve viewport on non-navigational changes

- Sub-layer toggles: show/hide layers only — no `fit`.
- Category change: fit to the newly visible content (current behaviour is correct).
- Expand/collapse: `invalidateSize` only, preserving centre and zoom — do not refit.

### 5. Verify

- Open FB02 → Irrigation tab → uncheck Zones → map keeps zoom/centre; tab stays on Irrigation.
- Pan and zoom, then toggle a sub-layer → viewport unchanged.
- Expand → switch to Trees → collapse → page shows Trees, map still framed on trees.
- Use the branch selector to move to another branch → full first-load behaviour (Summary, fit) — this reset is correct.
- Repeat 10+ interactions in mixed order; no snap-backs, no duplicated events.
- Portal map (HOA/PM/contractor) and the dashboard map preview behave exactly as before.

## Out of scope

- Changing the shared renderer's public API.
- Valve-box, icon, or basemap work.
- Persisting tab/sub-layer state across page navigations (only within a page session).
