# Task #344: Rebuild admin dashboard page to match super-admin mockup

**What/why:** Replace the current 8-static-cards admin dashboard with the ops-console layout in the attached mockup (`admin-dashboard-v4.html`). Depends on Task #343 (`GET /api/admin/dashboard`).

**IMPORTANT: the mockup HTML is attached to this task. Match its layout, spacing, colors, and typography as closely as possible — it already uses the admin portal's existing CSS variables and fonts.**

## Acceptance criteria

1. `artifacts/web-portal/public/admin/pages/dashboard.js` rebuilt to render, from one `GET /api/admin/dashboard` call:
   - Header row: title + global search input + "updated Xm ago" label. Search reuses the existing global admin search behavior if one exists; otherwise it navigates to the communities page with a `?q=` filter. Do not build a new search backend.
   - Row 1 — four KPI tiles: Communities, Active Assets, Incomplete Assets, Map Layers, with sublines from `totals`. Large numbers formatted (`1.42M`, `29,410` — thousands separators, M/k abbreviation ≥100k). Each tile navigates: communities / assets / assets?filter=incomplete / map-layers.
   - Row 2 — four exception cards from `exceptions`: overdue-work communities, unacknowledged >48h (subline "oldest waiting Nd"), quiet >14d, onboarding stalled. Each navigates to the communities or tasks page with a matching filter param (add the filter handling to those pages ONLY if trivial; otherwise navigate unfiltered and leave a TODO comment — do not scope-creep).
   - Left column: "Platform Activity" stacked bar chart (8 weeks, completed + still-open, CSS divs like the mockup — no chart library) and "Service Reliability" stat lines. If reliability fields are `null` (per #343), hide those lines.
   - Right column: "Business" stat lines (cents → `$1.24M`/`$318k` formatting), "Mapping Completeness" distribution bars, "Platform Users" stat lines.
2. All rendered strings from the API go through the shared escape helper (`VRTUtils.esc` if Task #340 has landed; otherwise a local `esc()`).
3. Loading state: keep current skeleton pattern. Error state: keep current retry-button pattern.
4. Auto-refresh every 60s using the existing pattern (no SyncManager dependency in admin; a simple setInterval cleared on route change is fine) and update the "updated Xm ago" label.
5. CSS added to `admin.css` using existing variables — no new fonts, no inline `<style>` blocks, no new libraries.

## Files involved

- `artifacts/web-portal/public/admin/pages/dashboard.js` (rewrite)
- `artifacts/web-portal/public/admin/admin.css` (new classes)
- Possibly small filter additions in `pages/communities.js` / `pages/tasks.js` (only if trivial)

## Must NOT change

- Router, shell templates, other admin pages' behavior.
- `/api/admin/summary` consumers.
- Any portal (`public/portal/`) code.

## How to verify

- Side-by-side with the mockup at 1280px and 1440px — layout matches, no horizontal scroll at 1024px.
- Numbers format correctly (0, small, and huge values); null reliability fields hide cleanly.
- Every tile/card/stat-line click navigates somewhere sensible; no dead cursors-pointer.
- No console errors; typecheck/build passes.
