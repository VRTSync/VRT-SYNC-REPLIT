# Task #489: Drop the deferred visibility refresh (follow-up to #481)

## What & Why

#481 correctly removed the 60-second auto re-render. One path back to the old behaviour survived.

`startRefreshInfra`'s 30-second label tick also retries a deferred refresh:

```js
setInterval(function () {
  updateRefreshLabel();
  if (_pendingVisibilityRefresh && document.visibilityState === 'visible') {
    maybeVisibilityRefresh();     // ← can trigger a full route re-render
  }
}, 30000);
```

If the user returns to the tab with stale data *while an interaction guard is active*, the refresh is deferred rather than dropped. Then, on any subsequent tick where the guard happens to read clear, the page fully re-renders.

The hole is that panning a map, zooming, toggling a sub-layer, and switching a category tab set **none** of the guards — they aren't an expanded panel, an open menu, or a focused input. So:

1. Expand the map on branch detail, switch tabs, return after 6+ minutes → correctly deferred.
2. Collapse the map, start panning.
3. Within 30 seconds the page rebuilds under the user: tab snaps to Summary, sub-layer selections lost, viewport refits.

That is the #481 bug, just rarer.

## Done looks like

- `_pendingVisibilityRefresh` and its retry branch are gone. The 30-second tick calls `updateRefreshLabel()` and nothing else.
- A refresh that is deferred by an active interaction guard is **discarded, not queued**. The label continues to age ("updated 9m ago"); the manual Refresh button remains available; the next `visibilitychange` to visible re-evaluates from scratch.
- No other code path can call `refreshCurrentRoute` except (a) a click on the Refresh button and (b) `visibilitychange` → visible with data older than `STALE_AFTER_MS` and no guard active.
- Everything else from #481 is untouched.

## Steps

1. Delete the `_pendingVisibilityRefresh` declaration, both assignments in `maybeVisibilityRefresh`, and the retry branch in the tick.
2. In `maybeVisibilityRefresh`, an active guard simply returns.
3. Re-read the file and confirm `refreshCurrentRoute` has exactly the two call sites above.

## Verify

- Branch detail → expand map → switch browser tabs → wait 6+ minutes → return → collapse the map → pan and zoom continuously for **two minutes**. The page must not re-render: tab stays put, sub-layer checkboxes stay as set, viewport stays where the user left it.
- Same setup, but on return leave the page completely alone for two minutes → still no refresh (it was deferred and discarded).
- Switch away and back again → now it refreshes once, label resets to "updated just now".
- Manual Refresh still works on every route.
- Navigate between all routes 10+ times → still exactly one interval and one visibility listener.
- The `tests/portfolio-refresh.spec.ts` suite still passes; add a case covering the discard behaviour.
