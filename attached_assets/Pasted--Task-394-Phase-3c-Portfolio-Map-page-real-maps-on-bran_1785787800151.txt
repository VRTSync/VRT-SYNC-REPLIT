# Task #394: Phase 3c — Portfolio Map page + real maps on branch detail

## What & Why

The portfolio's map surfaces are placeholders (#392). This slice makes them real: a **Portfolio Map** page showing every branch as a pin that drills into the branch, and **live Leaflet maps** on the branch detail layer tabs rendering that layer's geometry.

Two blockers must be solved first, both server-side:

1. **The client portal cannot read geometry today.** `GET /api/map-layers?communityId=` and `/api/map-layers/:id/geojson` are `requireAuth` but gate non-admins on **community membership** (`isUserMemberOfCommunity`). A `client_admin` is not a member of its branch communities, so both 403. Org-scoped read endpoints are needed.
2. **Communities have no coordinates.** `communities` has no latitude/longitude (unlike `tasks` and `assets`). Branch pins must derive a position from the branch's mapped geometry.

## Core principles

- **No changes to the existing `/api/map-layers/*` routes or their membership rules.** Add new org-scoped endpoints under `/api/portfolio/` instead — HOA/PM/contractor behavior must be untouched.
- **Derive branch coordinates, don't invent them.** Compute a centroid from the branch's layer geometry. A branch with no geometry has no pin and is listed separately as "Not yet mapped" — never place it at a default/fake location.
- Reuse the existing `/leaflet-map.html` template (served by the web-portal, driven by `postMessage` with `{ type: 'cmd', fn: … }`) rather than adding a map library to the portal bundle.

## Done looks like

- `GET /api/portfolio/branches/:communityId/layers/:layerId/geojson` returns that layer's GeoJSON, org-scoped (`requireClientOrAdmin` + org check). 403 across orgs.
- `GET /api/portfolio/map` returns `{ branches: [{ id, code, name, city, lat, lng, assetCount, openWorkOrders, hasGeometry }], unmapped: [{ id, code, name }] }` — coordinates derived from layer geometry centroids, computed server-side.
- **Portfolio Map page** (`#/map`, sidebar item "Portfolio Map"): Leaflet map with a pin per mapped branch; group filter chips; clicking a pin opens a branch card (name, code, services YTD, open work orders) with **"Open property map →"** which navigates to that branch's detail. An "Not yet mapped (n)" list appears when any branch lacks geometry.
- **Branch detail maps are live**: the Summary tab renders all of the branch's layers; each layer tab renders that layer's geometry highlighted with the others dimmed, matching the mockup's legend/toolbar treatment.
- Branches with no geometry keep the honest placeholder ("Not yet mapped") — no empty grey map, no console errors.
- Admin preview (`?org=`) works on both pages.

## Out of scope

- Editing geometry from the portal (read-only client view).
- Asset-level popups / clicking individual assets on the map (later slice).
- Changing Map Creator, the mobile app, or any admin map page.
- Satellite/base-layer switching beyond whatever the existing leaflet template already supports.

## Steps

### 1. Centroid helper — `artifacts/api-server/src/storage.ts`

- Add `getBranchMapPoints(orgId)`: for each community in the org, load its layers' `geojsonData`, compute a single representative point.
  - Prefer the centroid of the community-outline layer if one exists (`layerKey = 'outline'`), else the centroid of the bounding box of all features across all layers.
  - Use `@turf/area`-style math already available, or implement a simple bbox centroid — do **not** add a new dependency for this.
  - Communities with no layers or unparseable geometry → returned in `unmapped`, never given coordinates.
- Cache the result in-process for 60s (same pattern as `getAdminDashboard`), since parsing GeoJSON for 11+ branches on every page load is wasteful.

### 2. Org-scoped geometry endpoints — `artifacts/api-server/src/routes/routes.ts`

Both `requireClientOrAdmin`, both resolving the org exactly like the other `/api/portfolio/*` routes (admin may pass `?organizationId=`):

- `GET /api/portfolio/map` → `{ branches: [...], unmapped: [...] }` from step 1.
- `GET /api/portfolio/branches/:communityId/layers/:layerId/geojson` → verifies the community belongs to the caller's org **and** the layer belongs to that community, then returns `{ id, layerKey, subLayerKey, displayName, color, geojson }`. 404 if the layer isn't on that community (do not leak existence across orgs).

### 3. Portfolio Map page — `public/portfolio/pages/map.js`

- Register `PortfolioRouter.register('map', …)`; add "Portfolio Map" to `NAV_ITEMS`.
- Embed `/leaflet-map.html` in an iframe; wait for its ready message, then send pins via the existing `{ type: 'cmd', fn: … }` protocol. Follow how an existing portal page drives that iframe (`public/portal/pages/map.js`) — mirror the handshake, don't invent a new one.
- Pins: navy default, amber when `openWorkOrders > 0` (matching the mockup legend). Clicking a pin shows the branch card (rendered in the portal DOM, positioned over the map — not inside the iframe).
- Group filter chips filter which pins are sent.
- "Not yet mapped" list rendered below the map when `unmapped` is non-empty.

### 4. Branch detail — replace placeholders — `public/portfolio/pages/branch-detail.js`

- Summary tab: iframe map showing every layer of the branch.
- Layer tabs: same iframe, but the active layer's features styled prominently and other layers dimmed (send both sets; let the template style by layer id/color).
- Fetch geometry lazily per tab via the endpoint from step 2 and cache in memory for the current branch so tab switching doesn't refetch.
- Keep the panel header, "Open full map →" action (now a real link to `#/map`), and the legend from the mockup.
- If the branch (or the active layer) has no geometry: keep the existing placeholder copy, no empty map.

### 5. Verify

- As the PNC client user with FB02 mapped: Portfolio Map shows a pin at FB02's real location; unmapped branches appear in the "Not yet mapped" list; clicking FB02's pin → card → "Open property map" → branch detail.
- Branch detail Summary shows all FB02 layers; the Irrigation tab highlights irrigation geometry with others dimmed; switching tabs does not refetch (verify in the network tab).
- A client from another org requesting FB02's layer geojson → 403. A layer id from a different community → 404.
- Unmapped branch → placeholder, no console errors.
- Admin with `?org=` → identical behavior.
- HOA/PM/contractor map pages and admin map pages behave exactly as before (no regression from the new endpoints).
